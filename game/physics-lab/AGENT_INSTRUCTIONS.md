# PHYSICS LAB — AI開発エージェント向け指示書

## 作業開始前
1. MCPの `site/README.md` と、`site/game/` 配下の既存構成を確認する。
2. `site/game/physics-lab/PHYSICS_LAB_SPEC.md` を最初から最後まで読む。
3. 既存のRULES.md、PROGRESS.md、プロジェクト共通ルールがあれば必ず読む。
4. 既存の `populous` や `todofuken-board` など、他ゲームのファイルを変更しない。
5. 配信方式・パス・ビルド方法は site リポジトリの既存ルールに合わせる。

## 実装方針
- 仕様書の技術選定（Three.js + Rapier 3D + Vite + JavaScript ES Modules）を基本とする。
- まず Phase 1 のみを実装する。先のフェーズを先行実装しない。
- 物理演算、描画、入力、カメラ、ゲーム進行、UIの責務を分離する。
- 依存パッケージのバージョンを固定し、不要なライブラリを追加しない。
- ゲームプレイは通信なしで動作し、最終的に静的ファイルとして配信できる構成にする。
- 既存サイトのルートや他コンテンツに影響する設定変更を避ける。
- 仕様と実装が衝突した場合、独断で大きく変更せず、理由・影響・代替案を記録する。

## Phase 1 の実装範囲
- Three.js と Rapier の初期化
- SF研究施設をイメージしたテスト用床・壁・背景
- 物理剛体とColliderを持つ操作用球体
- 重力と床・壁との衝突
- WASD / 矢印キーによる移動
- Spaceによる接地中ジャンプ
- 球体を追従する三人称カメラ
- マウスによる視点変更（Pointer Lock対応。非対応時の代替も用意）
- ウィンドウリサイズ対応

## Phase 1 完了条件
- ブラウザで起動でき、実際に操作できる。
- 球体が重力で落下し、床・壁に正しく衝突する。
- WASDで移動し、Spaceでジャンプできる。
- カメラが滑らかに追従し、視点を変更できる。
- 床抜け、異常振動、操作不能が発生しない。
- ブラウザコンソールに重大なエラーがない。
- 本番ビルドが成功し、site配下での公開パスを考慮している。

## 作業終了時
1. 実装した内容と変更ファイルを列挙する。
2. 起動方法・確認URL・操作方法を記載する。
3. 実行したテストと結果を記載する。未実施のテストは未実施と明記する。
4. 既知の問題・未解決課題を列挙する。
5. `PROGRESS.md` が既にある場合は、日付・担当AI・実装内容・テスト結果を追記する。
6. Phase 1 の完了条件を満たしたら、そこで作業を停止して報告する。Phase 2へ進まない。

## 最初の依頼
上記を守り、仕様書に従って PHYSICS LAB の Phase 1 を実装してください。最初に既存環境を調査し、作業計画を立ててから着手してください。見た目の作り込みより、物理挙動・操作感・カメラ追従を優先してください。
