# PHYSICS LAB — 企画・実装仕様書

更新日: 2026-11-17
状態: 企画確定 / Phase 1 着手前

## 1. プロジェクト概要
近未来の物理研究施設を舞台にした、ブラウザ完結型の3D物理アクション・パズルゲーム。プレイヤーは実験用の球体を操作し、重力・反発・磁力・風力などの物理ギミックを利用してコースを攻略する。

### 確定方針
- タイトル: PHYSICS LAB
- ジャンル: 3D物理アクション / パズル
- 動作環境: Webブラウザ
- 描画: Three.js
- 物理演算: Rapier 3D（@dimforge/rapier3d-compat）
- 言語: JavaScript（ES Modules）
- 開発サーバー / ビルド: Vite
- UI: HTML / CSS / JavaScript
- カメラ: 球体を追従する三人称視点
- 世界観: SF・近未来研究施設
- 難易度: 適度に難しい。試行錯誤と攻略の達成感を重視
- 保存: LocalStorage
- プレイ人数: 1人
- 初期リリース: 5ステージ
- ゲームプレイに通信不要。ビルド済み静的ファイルで配信可能にする

## 2. ゲームの目的・基本ルール
各ステージのスタート地点からゴール装置まで到達する。コース上のクリスタルを収集し、クリア時間・収集数・リスポーン回数などで評価する。
基本ループ: ステージ選択 → 球体操作・攻略 → クリスタル収集・チェックポイント通過 → ゴール → リザルト確認 → 次ステージまたは再挑戦。

## 3. 操作仕様
| 操作 | キー | 内容 |
|---|---|---|
| 前進 | W / ↑ | カメラの水平前方を基準に移動 |
| 後退 | S / ↓ | カメラの水平後方を基準に移動 |
| 左右 | A / D | カメラ基準の左右移動 |
| ジャンプ | Space | 接地中にジャンプ |
| ブースト | Shift | 一時的に加速。クールダウンまたはゲージ制 |
| リスポーン | R | 最後のチェックポイントへ戻る |
| 一時停止 | Esc | ポーズメニュー |
| 視点 | マウス | カメラの方位・仰角を変更 |
- 入力処理はゲームロジックから分離する。
- ポーズ中・リザルト中は移動入力を無効にする。
- ブラウザのスクロール等がゲーム操作を妨げないようにする。
- マウス視点操作はPointer Lockを基本とし、解除・再取得を適切に扱う。未対応環境でも最低限プレイ可能にする。

## 4. プレイヤー・物理仕様
### 球体
- RapierのDynamic RigidBodyと球形Colliderを使用する。
- 重力、摩擦、反発、質量を設定可能にする。
- 地上では加速・減速に慣性を持たせる。空中操作力は地上より弱くする。
- 水平速度の上限を設定する。
- ジャンプは接地判定が成立している場合のみ可能。
- 見た目の回転は移動と同期させる。
- 操作性を優先し、現実の物理を完全再現する必要はない。
### 物理シミュレーション
- 固定タイムステップを基本60Hzとする。描画ループと物理更新を分離する。
- 経過時間を蓄積し、1フレーム内の物理ステップ数に上限を設ける。タブ復帰時の暴走を防ぐ。
- 単位系・重力・スケールを統一する。
- 高速移動時のすり抜け、床抜け、振動を検証する。
- Three.jsの表示オブジェクトとRapier剛体の位置・回転を同期する。
- 静的な床・壁はFixed RigidBody、プログラム制御の移動床はKinematic RigidBodyを基本とする。
- シーソーなど自由に動くものはDynamic RigidBodyとJointを使う。
- オブジェクト破棄時は剛体・Collider・Joint・イベント参照を適切に破棄する。

## 5. 三人称カメラ
- 球体の後方斜め上から追従する。
- 球体の移動方向に合わせてカメラ方位を自然に調整する。
- カメラ位置・注視点は補間し、急激に振れないようにする。
- マウスで左右・上下の視点変更ができる。仰角には上下限を設ける。
- 壁や床へのめり込みを防ぐ。必要ならRaycast等で位置補正する。
- ジャンプ中は少し引いた視点にするなど状況に応じた演出を加える。
- 落下・リスポーン・ステージ切替時にカメラを再同期する。
- 球体が画面から大きく外れないことを優先する。

## 6. 物理ギミック
各ギミックは独立モジュールとし、パラメータで調整可能にする。
1. JumpPad: 接触した球体に上向きの力または速度変化を与える。強度設定、多重発動防止。
2. RotatingPlatform: 指定軸・速度で回転する足場。球体が不自然に滑ったり置き去りになったりしないこと。
3. Magnet: 範囲内の球体に引力または斥力を与える。強度・範囲・極性・有効状態を設定し、力に上限を設ける。
4. WindZone: 範囲内の球体に指定方向の力を与える。方向・強度・範囲・有効状態を設定し、空中挙動も検証する。
5. Seesaw: 支点とJointを使い球体の重量で傾く。可動範囲・摩擦・減衰を調整し、振動や暴走を防ぐ。
6. MovingPlatform: 指定経路または始点・終点間を移動する。速度・待機時間・移動方式を設定し、球体を適切に運べること。

## 7. ステージ仕様
| ID | 名称 | 主な学習・攻略要素 |
|---|---|---|
| stage01 | 基本操作実験室 | 移動・停止・ジャンプ |
| stage02 | 重力実験室 | ジャンプ台・落下・高さ |
| stage03 | 運動実験室 | 回転床・移動床 |
| stage04 | 磁力実験室 | 磁力・シーソー |
| stage05 | 総合実験施設 | 全ギミックの複合攻略 |
各ステージにはID・名称・説明・スタート位置と向き・ゴール位置と判定範囲・床壁障害物・ギミックとパラメータ・クリスタル・チェックポイント・目標時間・ランク条件を定義する。
ステージはJSON等のデータで定義し、ゲーム本体を変更せず追加できる構造にする。座標系、角度単位、オブジェクト種別、必須項目、デフォルト値を明確にし、読み込み時に検証する。

## 8. ステージ攻略・評価
- ゴール接触時にクリア判定を一度だけ実行する。
- クリア時間、クリスタル取得数、リスポーン回数を記録する。
- S/A/Bの3段階評価。Sは目標タイム達成かつ全収集など厳しめ、Aは目標タイム内かつ一定数収集、Bは通常クリア。
- 各ステージの条件はデータで調整可能にする。
- ランク条件は画面上でも確認できるようにする。
- リザルトから再挑戦・次ステージ・ステージ選択へ移動できる。

## 9. チェックポイント・リスポーン
- チェックポイント接触で復帰地点を更新する。
- Rキーまたは落下判定で最後のチェックポイントへ戻る。
- リスポーン時は位置・向きを復元し、線速度・角速度をゼロにする。
- 必要に応じて接触状態や一時的なギミック状態を整理する。
- カメラを再同期し、リスポーン回数を記録する。
- 初期位置も最初のチェックポイントとして扱う。

## 10. UI・演出
近未来の研究施設を表現する。ダークブルー、シアン、白を基調とし、発光装置、ガラス状パネル、実験データ風表示を使う。視認性を優先し、球体・足場・危険箇所・ゴールを明確にする。
- HUD: 左上ステージ番号・進行状況、右上タイム・クリスタル数、左下操作ガイド、右下ブースト状態、中央付近に通知。
- 画面: タイトル、ステージ選択、ゲーム、ポーズ、リザルト、設定。

## 11. セーブデータ
LocalStorageにデータバージョン、解放済みステージ、各ステージの最高ランク、ベストタイム、クリスタル取得状況、解放済みスキン、設定情報を保存する。読み込み時に形式を検証し、不正・旧バージョンのデータで起動不能にならないようにする。保存失敗時もゲームは継続し、ユーザーに通知する。

## 13. パフォーマンス・品質要件
- 低スペックPCでも遊べるよう描画負荷を抑える。
- 物理演算対象を必要最小限にし、静的物体はFixed RigidBodyを使う。
- 毎フレームの不要なオブジェクト生成・破棄を避ける。
- ステージ切替時に前ステージの物理ボディ、イベント、描画オブジェクトを確実に破棄する。
- ウィンドウサイズ変更に対応する。
- タブ非表示・復帰時に物理演算が暴走しない。
- 依存ライブラリのバージョンを固定する。
- ビルド済み静的ファイルで動作することを確認する。

## 14. 開発フェーズと完了条件
### Phase 1: 基本物理環境（最初に実装）
Three.js初期化、Rapier初期化、簡単な研究施設の床・壁・背景、球体とCollider、重力・衝突、WASD移動、Spaceジャンプ、三人称追従カメラを実装する。
完了条件: ブラウザ起動、球体の落下と床衝突、WASD操作、ジャンプ、自然なカメラ追従、床抜け・異常振動なし、コンソールに重大エラーなし。
Phase 1完了後、操作確認できる状態で作業を止め、結果と未解決課題を報告する。Phase 2へ勝手に進まない。
### Phase 2: 操作とゲーム基盤
ブースト、落下判定、リスポーン、チェックポイント、ポーズ、HUDを実装・テストする。
### Phase 3: ギミック
6種類のギミックを個別実装し、それぞれ単体テスト用の小さな環境で挙動を確認する。
### Phase 4: ステージ
5ステージをデータで作成し、実際に攻略できることを確認する。
### Phase 5: ゲームシステム
タイム計測、クリスタル、ランク、ステージ解放、セーブ、リザルトを実装する。
### Phase 6: 演出と仕上げ
研究施設のデザイン、ライティング、パーティクル、サウンド、UIアニメーション、カメラ演出、パフォーマンス調整を行う。

## 15. テスト項目
- 球体が床・壁をすり抜けない。不自然に振動しない。
- 接地中だけジャンプでき、空中操作が強すぎない。
- 高速移動時に床抜けしない。
- 動く床に乗って移動できる。
- ギミックの連続接触で異常な力が加わらない。
- チェックポイントから正しい位置・向きに復帰し、速度・角速度が残らない。
- ゴール判定が一度だけ実行される。
- ステージ切替時に古い物理ボディが残らない。
- セーブ・ロードが正常で、ブラウザ再起動後も進行状況が残る。
- ウィンドウサイズ変更・タブ復帰後も正常に動く。

## 16. AIエージェントへの作業規則
作業開始時: リポジトリ構成を確認し、README・RULES・PROGRESS等があれば先に読む。既存ファイルや他プロジェクトを不用意に変更せず、既存の開発・配信方式に合わせる。
作業中: 一度に全機能を実装しない。各フェーズで動作する状態を維持する。実装済みと未実装を区別し、エラー原因を調査して修正する。実際にブラウザで動作確認する。仕様変更は理由と影響を記録する。
作業終了時: 変更ファイル一覧、実行したテストと結果、未解決課題を報告する。既存のPROGRESS.md等があれば作業ログを追記する。未確認の機能を完成扱いにしない。

## 17. 最初の実行指示
この仕様書を読み、まず既存環境を確認する。その後、Phase 1のみを実装する。最初の成果物は、ブラウザで球体を転がして操作感を確認できるプロトタイプとする。見た目の作り込みより物理挙動・操作感・カメラ追従を優先する。Phase 1の完了条件を満たしたら作業を停止し、動作確認結果と次フェーズへの課題を報告すること。
