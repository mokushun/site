# ゲーム性の実装（畑ごとの肥沃度・恵みの雨・作物の進化）— 指示書（Muse向け）

対象: site/game/populous/ の 3D版。主に prototype-3d-simulation.js、新規 prototype-3d-miracle.js、prototype-3d.js（配線）、prototype-3d.html（UI）。既存2D版 index.html は変更しない。

## 0. 作業の前に必ず読む
1. 作業場所の RULES.md と PROGRESS.md。

## 1. ユーザーの決定（この3つは変えない）
1. **肥沃度は畑ごとに差がつき、収穫のたびに下がる。** 全体で一律に上がるだけの仕組みをやめる。
2. **奇跡は「恵みの雨」。雨雲をプレイヤーが操作できる。使える量は「信仰心」で制限する。**
3. **肥沃な土地には新しい作物が育てられ、肥沃度が見た目で分かる。**

## 2. 守る制約
- MCP の変更は、1箇所だけの修正なら replace_in_file（old がちょうど1箇所に一致）を使う。大きな新規ファイルは write_file。1ステップごとに「書き込み→読み戻し→構文検査→ヘッドレス確認」。
- 変えない: terrainHeight / isWater / onLand / riverZ / lakeDefs、farmEnvironment（農地の配置条件）、treePositions / rockPositions、地形・水・自然のモジュール（terrain / water / nature の中身）。農地の置き場所の決め方（availableSpot の条件）は変えない。
- Three.js 0.180.0 CDN、外部画像なし（Canvas で手続き生成）。品質プリセット（?quality=low|high）に従う（low は軽くする。雨粒・作物の装飾の数を減らす）。
- 過去の事故を繰り返さない: モジュールのトップレベルで他モジュールの変数（THREE など）を参照しない／animate() 内で存在しない DOM を参照しない／改行を文字列 `\n` として書かない。
- 時間の流れ: 世界時計は 1秒=2分のまま。農地の収穫周期などの新しい時間は、シミュレーションの tick（現在5秒ごと）を単位にして、下の調整値の表に集める。

## 3. 設計

### 3.1 畑ごとの肥沃度
- 各畑（farm）が自分の肥沃度 fertility（0.05〜1）を持つ。新しい畑は、その場所の cells の肥沃度に、畑ごとのばらつき（位置から決まる乱数で ±0.12 程度、seeded を使う）を足して始める。畑ごとに差が出ること。
- 今の「畑が最寄りの cell の肥沃度を毎 tick コピーする」処理をやめる。畑の肥沃度は畑の中で独立に増減する。cells の肥沃度は、新しい畑の初期値と、地面の色づけにだけ使う（雨がかかった場所は cells も少し上げてよい）。
- 水辺に近い畑（waterDistance が小さい）は、収穫での肥沃度の減りを少し軽くする（最大 -30%）。地形の違いが効くようにする。
- 食料の生産は、畑ごとの肥沃度と作物の種類から計算する（3.2）。平均肥沃度は、HUD に畑の平均を出す（畑が0枚のときは「—」）。

### 3.2 収穫サイクル
- 各畑は、植え付け→成長→収穫→（肥沃度が下がる）→植え直し、を繰り返す。成長の長さは調整値の表のとおり。
- 収穫の瞬間に、(a) 食料が増える、(b) その畑の肥沃度が作物ごとの値だけ下がる、(c) 信仰心が少し増える（3.3）、(d) 作物の見た目がいったん収穫後（低く・まばら）に戻り、また育ち始める。収穫がプレイヤーに見えること（作物がぐんぐん伸びて、収穫でしぼむ）。
- 収穫量 = 作物ごとの基本量 × (0.4 + 肥沃度)。
- 畑の自然回復は、とても遅い（収穫の減りより小さい）。放っておくと、ゆっくり痩せていく。畑が痩せて収穫が減ると、人口が養えなくなる。この緊張感が本題。
- 既存の「食料が足りないと人口が減る」「食料・木材があれば農地と住宅が自動で増える」はそのまま使う。ただし、新しい生産量に合わせて、農地の増築のしきい値（food>35 など）が不自然にならないよう調整する。

### 3.3 信仰心
- 信仰心 faith（0〜上限）。上限 = 40 + 住宅数×8。
- 増える条件: (a) 住民が食料に余裕があるとき、毎 tick に 人口×0.1（食料 > 人口×2 のときだけ）。(b) 収穫のたびに、作物の等級に応じて +1 / +2 / +3。
- 減る条件: 恵みの雨の使用（3.4）。住民が餓死で減ったとき -5（下限0）。
- 信仰心は HUD に表示する（数値とバー）。足りないとき、恵みの雨ボタンは無効（灰色）にして、ツールチップで理由を出す。

### 3.4 恵みの雨（雨雲の操作）
- HUD の「恵みの雨」ボタンで、雨雲を呼ぶ（信仰心が最低値以上のとき）。もう一度押す、Esc、または信仰心が0になると、雨雲は消える。
- 雨雲は、ポインタ（マウス）の指す地面の位置へ、滑らかに追従する（毎フレーム、ポインタの Raycast 位置へ補間）。カメラ操作（ドラッグ・ホイール）は今までどおり使えること（雨雲の呼び出し中も妨げない）。
- 雨雲の見た目: 既存の雲（クラウドの質感）を使い、少し暗い灰色にした、やや大きめの雲。地面に雲の影（薄い楕円）を落としてもよい。
- 雨は雲の真下にだけ降る（半径4程度の円柱の範囲）。範囲内の畑の肥沃度が、雲の中心に近いほど速く上がる。範囲内の cells の肥沃度・水分も少し上がる。雨粒は雲の下から地面へ落ちる粒（数は quality で調整）。雨雲を動かして、畑を順に潤すのが遊びになる。
- 信仰心の消費は、雨が降っている間、毎秒かかる（調整値の表）。畑の肥沃度の上がり方は、消費に見合う水準にする（1回で全畑を満たせない）。
- 既存の「土地肥沃化」ボタン（無料の肥沃化）と、無料の「雨」ボタン（startRain）は廃止する。肥沃度を上げる手段は、恵みの雨だけにする。関連する配線（prototype-3d.js、prototype-3d.html の #fertilityTool / #rain、simulation の setMode / handleClick の肥沃化処理）を整理し、消し残しで null 参照が起きないようにする。

### 3.5 作物の等級と肥沃度の見た目
肥沃度に応じた3つの等級。等級の切り替えは、植え直しのとき（収穫の直後）に判定する（ちらつき防止のため、上がるしきい値と下がるしきい値に幅を持たせる）。

| 等級 | 作物 | 条件（植え直し時の肥沃度） | 見た目 | 収穫量（基本量） |
|---|---|---|---|---|
| 1 | 麦 | 既定（〜0.6） | 細い茎＋黄金色の穂。痩せると黄ばんで短い | 小 |
| 2 | 豆・野菜 | 0.6 以上（下がるのは 0.55 未満） | 緑のこんもりした株が畝に並ぶ。支柱と小さな花・さや | 中 |
| 3 | 果樹（またはひまわり） | 0.8 以上（下がるのは 0.75 未満） | 背の高い低木に赤・橙の実、または大きな黄色い花。畑全体がはっきり華やか | 大 |

- 土の色: 肥沃度が高いほど濃くて黒っぽい湿った土、低いほど白っぽく乾いた土。ひび割れの模様（Canvas で生成、低肥沃度のときだけ見える）を重ねてよい。
- 肥沃度が低い畑（約 0.25 未満）は、作物がしおれて見える（色が褐色寄り・背が低い・傾く）。
- 肥沃度が高い畑には、見える目印を付ける（例: 畑のふちに小さな花、まれに舞うきらめき粒子。high のみ）。「あの畑は肥沃だ」とひと目で分かること。
- 作物の見た目を作るコードは、新規 prototype-3d-crops.js に分ける（等級ごとのメッシュ生成と、成長・しおれの更新）。simulation.js は呼び出すだけにする。

### 3.6 畑の情報表示
- 畑をクリックすると、その畑の情報パネルを出す（HUD の隅。#farmInfo など）: 作物の名前（麦／豆・野菜／果樹）、肥沃度（％）、次の収穫までの目安、収穫量の目安。もう一度クリック・Esc・別の場所のクリックで閉じる。
- 畑の選択のためのクリック判定は、畑のグループへの Raycast を使う。恵みの雨の呼び出し中にクリックしても、誤って閉じたりしない（雨雲の操作を優先する）。

### 3.7 HUD と UI
- 追加: 信仰心（数値＋バー）、恵みの雨ボタン、畑の情報パネル。
- 削除: 土地肥沃化ボタン、雨ボタン。
- 変更: 「平均肥沃度」は畑の平均。メッセージ欄（#mode）に、収穫・作物の進化（「畑が肥沃になり、豆が育つようになった」）・信仰心の不足などを出す。
- 既存の HUD の ID（#food #wood #population #farms #fertility #mode #clock など）は維持する。

## 4. 調整値（初期値。prototype-3d-simulation.js の冒頭に TUNING として1か所にまとめる）

| 信仰心 増加（余裕時） | 人口×0.1 / tick |

実装: 2026-11-22 / Muse（本チャット）。全ステップ完了。

- ステップ6 バランス検証（Node でシミュレーションを駆動、水辺距離3の条件）:
  - (a) 雨なし: 平均肥沃度 71→12（240 tick）、食料は枯渇し人口 14→7、信仰心も餓死で減少。意図した緊張感の弧を確認。
  - (b) 雨あり（痩せた畑に6秒ずつ）: 肥沃度は約60で安定、食料は増加、人口は住宅上限付近で安定。
  - (c) 信仰心: 雨の消費（2/秒）は余裕時の増加＋収穫ボーナスと釣り合い、70〜80を往復。
  - 麦畑（肥沃度0.5、水辺距離3）: 1サイクルの正味は約-0.024 → 0.3 まで約8回の収穫で、指示書の目安（約7回）に近い。水辺から遠い畑は約6回と速く痩せる。

- 追記（2026-11-23、ユーザー報告「農地が2から増えない」を受けて）: 原因は収穫モデルではなく出生管理の不具合だった。餓死で人口が減っても家の occupants が減らないため、全戸満員と判定されて出生が止まり、人口連動の農地上限に張り付いていた。餓死時に occupants を解放するよう修正。調整値の変更: 出生の食料しきい値 人口×4 → 人口×3（理由: 収穫が波打つ新モデルでは ×4 が厳しすぎ、序盤の停滞を招くため。指示書 3.2 の「しきい値が不自然にならないよう調整する」に従う）。実地形3件で修正前は農地1〜3枚・人口3〜14で停止、修正後は農地9〜10枚・人口48〜51まで成長を確認。
- 追記（2026-11-23、ユーザー報告「信仰心が増えない・人口が増えない」を受けて）: 信仰心が雨の最低値10に届かない村では、収入（収穫のみ）より餓死ペナルティ（-5）が勝ち、信仰心が0付近に張り付いて回復不能になる詰みがあった。調整値の追加: faithFloorRate = 1/tick（信仰心が10未満のときだけ、10まで回復する下限）。健全な村の収支は不変で、崩壊した村でも雨を再開して立て直せることを長期駆動で確認した。
- 注意（指示書との差異）: §2 の「世界時計は 1秒=2分のまま」は、ユーザーが同日に別途「時間経過を3倍に」と指示し、実装済み（utils の WORLD_MIN_PER_SEC=6、1日≒4分）のため、そちらを優先して時計には触れていない。収穫・信仰心は tick（5秒）単位なので、この差異はゲーム性に影響しない。
