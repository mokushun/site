# 3D版グラフィックスのリアル化 — 実装指示書（Muse向け）

作成: 2026-11-21 / Claude（VPS開発プロジェクト）。ユーザーの指示:「ポピュラス3Dのグラフィックスをもっとリアルにしたい。Muse に実装させる」。
対象: site/game/populous/ の 3D版（prototype-3d.html / .css / .js / -buildings.js / -simulation.js）。既存2D版 index.html は変更しない。

## 0. 作業の前に必ず読む
1. 作業場所の RULES.md と PROGRESS.md（作業ログの書き方は RULES.md「2.」）。
2. prototype-3d.html（importmap の three と addons のパス・バージョンを確認。Three.js 0.180.0 CDN固定）。
3. prototype-3d.js、prototype-3d-buildings.js、prototype-3d-simulation.js、README.md。
4. 現状を壊した過去の事故（PROGRESS.md 2026-11-18〜19）: (a) モジュールのトップレベルで、他ファイルの import 変数（THREE）を参照して ReferenceError → 画面が出ない。(b) 書き込み時に改行が文字列 `\n` として混入し構文エラー → 3D画面が出ない。(c) animate() 内で存在しない DOM を参照して null 例外 → ループ停止。同じことを起こさないこと。

## 1. 守る制約
- MCP はテキスト専用・1ファイル1MBまで。画像・バイナリは置けない。テクスチャは Canvas／コードで手続き生成する。外部の画像URLに依存しない。
- 外部読み込みは既存と同じ Three.js CDN（importmap）のみ。addons を使う場合は importmap に追記し、バージョンを 0.180.0 に揃える。
- シミュレーションの論理（prototype-3d-simulation.js の経済・人口・建設の計算、住民の役割動作、farmEnvironment、UI の ID）は変えない。見た目の層だけを変える。terrainHeight・isWater・onLand・riverZ・lakeDefs の関数と値も変えない（農地判定・住民移動がこれに依存している）。ただし地形メッシュの色や材質は変えてよい。
- 1ファイルが大きくなりすぎるため、新しい描画コードは新ファイルに分けてよい（例: prototype-3d-materials.js、prototype-3d-atmosphere.js、prototype-3d-vegetation.js）。ES モジュールは、必要な THREE などを引数で受け取る関数にして、トップレベルで他モジュールの変数を参照しない。
- 品質プリセット（low / high）を持つ。low は現行同等の負荷以下、high で全機能。切替は URL の `?quality=low|high`（既定は high）と、画面のボタン1つ（任意）。ヘッドレス検証など低性能環境でも動くこと。
- ブラウザ実機の確認はユーザーが行う。Muse は、書き込み後の読み戻し（sha256）、構文検査（node --check 相当）、可能ならヘッドレス Chromium で Console エラー0件の確認までを行い、できなかったことは「未確認」と書く。
- 1ステップごとに「書き込み→読み戻し→検査」をして、段階的に進める。まとめて大改修をしない。

## 2. 実装ステップ（この順。1ステップ完了ごとに PROGRESS.md へ記録）

### ステップ0: 準備
- 現状の見た目の特徴を README の追記用に箇条書きにする。品質プリセットの枠組み（`quality` 変数と、各機能がそれを見る形）だけを先に入れる。

### ステップ1: 空と光（最優先）
- 単色背景を、空（addons の `Sky`、または空色グラデーションの背景球）に替える。
- 空から PMREM で環境マップを作り、`scene.environment` に設定する（影の側に空の色が回り、立体感が出る）。
- 霧の色を地平線の色に合わせる。ACES の露出を調整する。
- 影の解像度を high で 4096、low で 2048 にする。normalBias を調整して影のにじみ・アクネを確認する。

### ステップ2: 地形のテクスチャ
- Canvas のノイズで、草・土・岩・湿った砂の4種の色テクスチャと、簡易の法線マップを生成する。
- 地形マテリアルを `onBeforeCompile` で拡張し、高さ・傾斜・水際の近さで4種を混ぜる（急斜面は岩、水際は湿った砂、平地は草）。
- 近景用の細かい模様を、2つのスケールで重ねる（タイルの繰り返しが目立たないように）。既存の頂点カラーは弱く残して、色の大きなむらに使う。
- 地形の頂点数（112 分割）は、low では変えず、high でも必要がなければ変えない。

### ステップ3: 水
- 湖・川（waterMat）を、動く法線マップ（Canvas で生成、UV スクロール）に替える。空の反射はステップ1の環境マップを使う。
- 岸近くは透け、岸に白い泡の帯がつくようにする（頂点カラー、または地形との高さ差で決める）。遠景の海は、色と反射を整える程度にする。

### ステップ4: 植生と岩
- 広葉樹の樹冠を、球1個から、ノイズで歪めた球3〜4個を合成した形に変える。インスタンスごとに色（setColorAt）と大きさを変える。針葉樹も、円錐を2〜3段重ねた形にする。
- 風でわずかに揺らす処理を、頂点シェーダーの追加（onBeforeCompile）で入れる。high のみ。
- 岩は、頂点をノイズで変位させた不規則な形にする。大小の岩を足し、地形に少し埋める。
- 草の房（交差した板＋ Canvas で生成した草テクスチャ、alphaTest）、低木、花をインスタンスで撒く。農地・水・建物・住民の経路になる場所の近くは避ける。数は high のみ多め、low は少なめ。
- 重要: `treePositions` と `rockPositions` は farmEnvironment（農地の配置判定）が使うため、変数名と内容（x, z の配列）を維持する。木・岩の置き場所の決め方（seeded 乱数のしきい値）は、農地の配置に影響するため、不必要に変えない。

### ステップ5: 建物と住民の質感（優先度 低）
- prototype-3d-buildings.js の壁（漆喰）・木・屋根瓦に、Canvas で生成した質感を付ける。建物の形・配置・足場演出は変えない。
- 住民は、体の比率や服の質感を少し整える程度にする（役割動作の腕・斧のグループ構造は変えない）。

### ステップ6: 大気と時間（任意）
- 画面の WORLD TIME と太陽の位置・色を連動させる（朝焼け・昼・夕焼け・夜。ただし夜は暗くしすぎない）。時間が停止中は固定する。
- 雲の質感、遠くの鳥、舞う塵などを足す。軽いブルーム（UnrealBloomPass、addons）は high のみ。重ければやらない。

### ステップ7: 性能と仕上げ
- 品質プリセットの切替が全機能で効いていることを確認する。fps が極端に落ちる機能は、high でも数を減らす。
- README.md に、構成（新しいファイル）、品質プリセット、各機能の説明、未実装・未確認の点を追記する。

## 3. 完了の目安（ユーザーが実機で確認する）
- 起動直後に Console のエラーが 0 件。時間進行ON・OFF、住民・建物・雨・肥沃度クリックが従来どおり動く。
- 地形に草・土・岩・砂の変化が見え、遠くから寄っても塗り絵に見えない。水が動き、岸に泡がある。木・岩・草のばらつきがある。
- ?quality=low で、従来と同等以上の fps で動く。

### ステップ0・1（2026-11-21 / Muse）
- ステップ0: 品質プリセットの枠組みを prototype-3d.js に実装。`?quality=low|high`（既定 high）、画面の「画質」ボタンで切替（再読み込み方式）。pixelRatio は high 1.8 / low 1.25。現状の見た目の特徴は README.md の「3Dグラフィックスのリアル化」節に箇条書きした。
- ステップ1: 空を addons の Sky に置き換え（importmap に three/addons/ を追加、0.180.0）。PMREM で環境マップを生成して scene.environment に設定（environmentIntensity 0.5）。霧の色を 0xbcd3da に変更、ACES 露出 1.08→1.0、半球光 1.65→0.85。影解像度は high 4096 / low 2048（normalBias は現行 0.025 を維持）。
- 検証: 書き込み後の読み戻し sha256 一致。構文検査 OK。ヘッドレス Chromium（ローカル配信、three は CDN と同一ファイル）で high の描画・時間進行・シミュレーション動作を確認し、Console エラー0件（favicon の 404 を除く）。スクリーンショットで空のグラデーションと地形の質感を確認。
- 未確認: 実機での見た目（色味・影のにじみ）と fps。ユーザーの確認待ち。

### ステップ2（2026-11-21 / Muse）
- Canvas のバリューノイズ→カラーランプで草・土・岩・湿った砂の4テクスチャ（256px）と bump 用ノイズを生成。地形マテリアルを onBeforeCompile で拡張し、ワールド座標の高さ・傾斜で混合（岩: 傾斜 smoothstep 0.12〜0.32＋高所補正、湿った砂: 高さ 0.10〜0.0、水際の低地）。近景 0.55 / 遠景 0.045 の2スケール。頂点カラーは混合率 0.42 の弱い色づけとして残置。地形ジオメトリに uv 属性を追加（bump 用、bumpScale 0.15）。high のみ有効で、low は従来の頂点カラーのみ。
- 検証: ステップ0・1と同一のヘッドレス確認で、low でもエラー0件・描画を確認。地形の草／土／砂の混合はスクリーンショットで確認。
- 未確認: 実機での近景の繰り返し感と bump の強さ。ユーザーの確認待ち。ステップ3以降は確認後に進める。

### ステップ3（2026-11-21 / Muse）
- 湖・川の waterMat に、正弦波合成の高度場→Sobel 変換で作ったタイリング可能な法線マップ（256px）を設定し、animate() で UV オフセットを毎フレームスクロール（0.021 / 0.014）。roughness 0.22→0.16、opacity 0.94→0.92。反射はステップ1の環境マップ。
- 湖3か所に泡リング（放射グラデーション＋斑点の Canvas テクスチャ、楕円に拡大、水面と同じ waterGroup 内で上下動に追従、renderOrder 2）。
- 海（oceanMat）にも同じ法線マップを repeat 26 で適用し、roughness 0.28→0.17、スクロールは湖より低速。
- 川の泡は未実装（チューブ形状に沿わせるのが難しいため、法線と反射のみ）。岸の透けは opacity 調整のみで、シェーダによる水深フェードは入れていない。
- 検証: 書き込み後の読み戻し sha256 一致、構文検査 OK。ヘッドレス Chromium で high / low ともエラー0件、描画・時間進行・農地生成を確認。スクリーンショットで湖岸の泡リング（淡い縁）を確認したが、この距離では控えめ。実機での強さの判断はユーザー待ち。

### ステップ3 修正（2026-11-21 / Muse、ユーザー指摘「泡が浮いてる」）
- 原因: 泡リングが水面より上の別平面（y=-0.012）だったため、傾斜した岸では板のように浮いて見えた。
- 対策: リング面と泡テクスチャ生成を削除し、泡を湖の水面マテリアル自体のシェーダに移した。湖ジオメトリにローカル座標と半径（rx, rz）を属性として持たせ、縁の帯（正規化半径 0.74〜0.97）を時間でわずかに明滅させながら白くする。水面と同一面なので浮くことはない。川・海は変更なし。
- 検証: 構文検査 OK、ヘッドレス Chromium でエラー0件。全体表示と拡大表示のスクリーンショットで、泡の縁が水面に密着していることを確認。

### ステップ4（2026-11-21 / Muse）
- 広葉樹: 樹冠を球1個から、位置ハッシュのノイズで歪めた球4個の合成に変更。マテリアル別の4分割をやめ、単一 InstancedMesh＋setColorAt で個体ごとに色（従来パレット＋HSL の微 variation）と大きさを変えた。針葉樹: 円錐を3段重ねにし、同じく単一メッシュ＋個体色。
- 風揺れ: 樹冠マテリアルに onBeforeCompile で頂点シェーダを追加（インスタンス位置を位相に、高さで重み付け、振幅 0.045 以下）。high のみ。幹は揺らさない。
- 岩: 十二面体の頂点をノイズ変位させて不規則化し、配置 y を +0.18→+0.07 に下げて地中に少し埋めた。岩の追加はしていない。
- 草・低木・花: 草の房（交差2面＋Canvas 草テクスチャ、alphaTest 0.42）、低木（歪めた小球）、花（茎＋色つき小球、白・黄・桃・赤）をインスタンス散布。水・急斜面（勾配 0.55 超）・中心 7.5 以内を回避。数は high で草およそ数百〜千超・低木最大140・花最大260、low は出現率を下げて削減。
- 保護対象の確認: 木と岩の配置判定（seeded の呼び出し順と treePositions / rockPositions への push）は従来と同一で、色付け用の追加 seeded 呼び出しは純関数のため配置に影響しない。
- 検証: 構文検査 OK。ヘッドレス Chromium で high / low ともエラー0件、描画確認。スクリーンショットで樹冠のばらつきと岩の不規則化を確認。風揺れは静止画では未確認（実機で確認）。

### ステップ4 修正（2026-11-21 / Muse、ユーザー実機報告「岩は割れ目があるね。水面は浮いたまま」）
- 岩の割れ目: 原因は、十二面体（面ごとに頂点が分かれ、法線が面ごとに違う）を法線方向に変位させたため、角で頂点が離れたこと。中心から外向き（位置方向）に変位させる displaceRadial に変更し、同じ角の頂点が同じだけ動くようにした。
- 水面の浮き: 泡を水面に描く方式にした後も、水の円盤の縁がくっきりして板のように見えた。縁に近づくほどアルファをフェードさせて岸と馴染ませ、泡の帯も内側に寄せ、円盤を 0.97 倍に縮小して窪みに収めた。
- 検証: 構文検査 OK、ヘッドレス Chromium でエラー0件。拡大スクリーンショットで川の縁のフェードを確認（湖の寄りは次回確認）。

### 緊急修正（2026-11-21 / Muse）: 読み込みが止まる不具合
- 症状: 他AIの修正後、ページの読み込みが止まる（メインスレッドがブロックされ、描画もコンソール応答もなし）。
- 原因: 岩の配置ループの内側の条件が `x<=20` ではなく `z<=20` になっていた。z は外側ループの変数で内側では変化しないため、内側ループが無限ループになっていた。
- 修正: 条件を `x<=20` に戻す1文字修正のみ。他AIの変更（海 -1.45、waterMat の depthWrite:false、湖の水位 -0.04 と泡帯・フェード値、岩の放射変位）はそのまま維持。
- 検証: 構文 OK、ヘッドレス Chromium で Canvas 生成・人口表示・エラー0件を確認。

### 川の浮き修正（2026-11-21 / Muse、ユーザー実機報告「森の中の水面はまだ浮いてる」）
- 対象は川。従来は川底の高さに中心を置いた半径 0.36 のチューブで、岸より上に膨らみ、特に森の中ではホースが乗っているように見えた。
- 川底 +0.17 の高さに沿う平らなリボン（幅 1.1、川の中心線に垂直に展開）に置き換え。縁は岸の地形に隠れるため、地形に沈んで見える。法線マップとスクロールは従来どおり waterMat を共用。
- 検証: 構文 OK、ヘッドレスでエラー0件、スクリーンショットで森の中を流れる川が地形に沿うことを確認。

### 森の湖の浮き修正（2026-11-21 / Muse、ユーザー実機報告）
- 対象は森のそばの湖（川ではない、とユーザー訂正。前ターンの川リボン化は誤読によるものだが、見た目の改善として残置。不要なら戻す）。
- 原因: 湖の水位が全湖共通の -0.04 固定で、斜面にある湖では下り側で円盤の縁が窪みの外に出て浮いて見えた。平らな場所の湖は直っていた。
- 修正: 湖ごとに縁（楕円周上64点）の地形高さを測り、水位をその最低点より 0.03 下に設定。全周で岸が水位より高くなり、岸が閉じる。isWater 等の判定は無変更（描画上の水位のみ）。
- 検証: 構文 OK、ヘッドレスでエラー0件、スクリーンショットで森の湖の縁が地形に収まることを確認。
### 湖面の欠け・半月状表示の修正（2026-11-21 / ChatGPT）
- ユーザーの実機スクリーンショットで、右側の湖が半分だけ見え、地形に水面を大きく切られたように見える状態を確認。
- 原因: 湖の水面メッシュは湖沼半径の 0.97 倍で描いているのに、水位計算では元の半径（1.0倍）の円周をサンプリングしていた。実際の水面の縁と水位計算の縁が一致せず、傾斜地では水面メッシュの内側を地形が横切る可能性があった。
- 修正: 水面メッシュと同じ lakeRx/lakeRz（0.97倍）で128点をサンプリングし、その最低地形高より0.045下に水位を置く。湖の円周分割も48から128へ増やし、近距離での多角形状の縁を抑えた。地形・水域判定・農地判定・シミュレーションは変更なし。
- 検証: MCP書き込み後に読み戻し、修正箇所の一致を確認。ブラウザ実機・ヘッドレス実行は未確認。ユーザーの強制再読み込み後に、3つの湖が欠けずに見えるか確認する。
